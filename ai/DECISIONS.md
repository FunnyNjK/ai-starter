# Architecture Decision Records

Last Updated: 2026-05-10

This file records decisions that affect architecture, dependencies, security,
deployment, testing, or scope. Each ADR captures what was decided, why, and
what trade-offs were accepted. ADRs are written sequentially (ADR-001,
ADR-002, ...) and are immutable once accepted — to change a decision, write
a new ADR with status "Accepted" that supersedes the previous one and mark
the previous one "Superseded".

Project-specific ADRs are added during initialization (P0-T1) and as the
project evolves. At minimum, each major choice — language, framework,
package manager, testing tools, hosting target, CI system — should have its
own ADR so future contributors can see *why* the choice was made.
