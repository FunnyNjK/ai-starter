# Recipe: TypeScript Library (tsup + changesets)

Last Updated: 2026-05-21
Applies to: Library / package platform + TypeScript language.

## What this template gives you

A TypeScript library packaged for distribution via npm. tsup
bundles to ESM + CJS + type declarations. changesets handles
release automation. Vitest for tests, ESLint + Prettier for
lint/format.

## Design philosophy

- **Dual ESM + CJS output.** Modern consumers get ESM; legacy
  CommonJS consumers still work. `package.json` `exports` field
  routes both.
- **TypeScript declarations shipped, source not.** Consumers see
  `.d.ts` files; the `.ts` source stays in `src/` (not published).
- **Changesets for releases.** PR authors add a `.changeset/*.md`
  file describing the change + semver bump. CI consumes pending
  changesets, generates CHANGELOG entries, publishes to npm.
- **Zero runtime deps if possible.** Library deps become consumer
  deps; minimize the blast radius.
- **Public API is a single entry point.** Default exports
  discouraged. Named exports from `src/index.ts` are the public
  surface; anything not in `index.ts` is private even if
  technically reachable.

## Folder layout

```
projects/<name>/
├── src/
│   ├── index.ts            # public API entry point
│   └── ...                 # internal modules
├── tests/
├── .changeset/
│   └── config.json
├── tsconfig.json
├── tsup.config.ts
├── package.json
├── pnpm-lock.yaml
├── README.md
└── CHANGELOG.md            # generated by changesets
```

`package.json` exports field shape:

```json
{
  "main": "./dist/index.cjs",
  "module": "./dist/index.js",
  "types": "./dist/index.d.ts",
  "exports": {
    ".": {
      "import": "./dist/index.js",
      "require": "./dist/index.cjs",
      "types": "./dist/index.d.ts"
    }
  }
}
```

## Local dev story (P1-T1 scaffold target)

1. `pnpm install`
2. `pnpm dev` — tsup in watch mode rebuilds on change.
3. `pnpm lint && pnpm typecheck && pnpm test && pnpm build` —
   all four exit 0. `dist/` contains ESM + CJS + `.d.ts`.
4. `pnpm changeset` — interactive prompt to add a changeset for
   the current branch's work.

No docker-compose. No DB. Library deps only.

## Free-tier ceilings to record at init

- npm registry is free for public packages. Scoped private
  packages require a paid npm account — capture in BUDGET.md if
  the library is going to be private.

## Production handoff (deferred to P3-T0)

For libraries, "production" = published to a registry. The deploy
plan is the CI publish pipeline:

- changesets/action runs on `main` after PRs merge.
- If pending changesets exist, opens a "Version Packages" PR.
- Merging that PR runs `changesets publish` to npm with an OIDC-
  authenticated npm token (via npm Trusted Publishers, no
  long-lived tokens).

P3-T0 records: npm scope, public/private, the OIDC trust setup,
versioning policy (semver), CHANGELOG generation policy.

## When to pick this

- You're shipping reusable TypeScript code (utilities, SDKs,
  framework plugins) for other developers to import.
- Dual ESM + CJS output matters.
- Automated semver via changesets is a feature.

## When NOT to pick this

- You're shipping a CLI rather than a library — use the Node CLI
  recipe (not in v1.2.0; pick Custom).
- You need C# / Python / Go library distribution → different
  ecosystems, different recipes.
